Seahorse: a memory for a frozen language model

Can a model that is never retrained remember what you told it in an earlier conversation? A vector pushed into its activations carries a leaning, but not a fact. A small stored slice of the model’s own attention memory, put back in the right place, carries the fact. This page explains both results, where the second one breaks, and where the project goes next.

Vedant Jumle · independent project · Paper 1: What Survives When Activation Steering Is Used as Memory (arXiv:2610.14958) · code and run reports

Summary

  • The question. Can a frozen language model form a memory in one conversation and use it in a later one, with no training and without pasting the old conversation back in? Every result below is read against two anchors: no memory, and the original sentence written into the prompt.
  • A pushed vector carries a leaning, not a fact. In a pre-registered run on Qwen3.5-2B and 9B, with every answer judged for direction and coherence and the judge checked by models from other families, a stored preference moves answers by {{LEAN1_2B_V}} (2B) and {{LEAN1_9B_V}} (9B) on a −1..+1 scale, and only near one dose. Facts are used cleanly in at most {{PUSH_MAX}} of answers, against {{FACT_CTX}} with the fact in context. Yes/no questions about the fact never improve. This is paper 1.
  • Facts are bound by position, and a stored slice supplies one. In context, the answer reads “Pepper” from the name’s own position; the question’s subject holds no copy of it. Keeping the attention keys and values of just two positions (the name and the full stop) and putting them back into the next session’s user turn gives clean use {{R25_MIN}} on Qwen2.5-1.5B. The same two tokens as plain text give {{TMIN25}}, the pushed vector at most {{PUSH_MAX}}, the sentence in context {{CTX25}}.
  • Where it breaks. Facts stored in separate sessions and put back together swap partners in {{COLL_RANGE}} of answers. Finding the right slice by the subject’s words works {{GK_K1}} of the time among {{GK_N}} stored facts, but a wrong pick produces a confident wrong fact.
  • The model can write its own references. Storing a preference needs comparison sentences (its opposite, some alternatives). A 9B model wrote them, and paper 1’s main direction result reproduced with no hand-written reference (on dislikes, {{GEN_OPP_DIS}} with the generated opposite against {{HAND_OPP_DIS}} with the hand-written one). Reading whether a preference is a like or a dislike, automatically, is still open.
  • The direction. Slices for content, the push for abstracted leanings, and an offline “dreaming” phase for what one forward pass can’t do: re-encoding memories that belong together, abstracting leanings from episodes, choosing what to keep. A small trained read adapter on the frozen model is the likely next step.

1The question

A language model has two kinds of memory. Its weights are permanent but slow to change. Its context is instant, but it disappears when the session ends. Nothing sits in between: no fast, lasting memory that forms from experience, the role the hippocampus plays in animals (the project is named after it; hippocampus is Greek for seahorse).

Seahorse tries to build that middle piece for a model whose weights never change. The aim is a memory rather than a record. A record is a transcript you search and paste back. A memory is compact, it is stored from the model’s own internal states, and it comes back when the present resembles the past, in the spirit of the hippocampal index theory, where the hippocampus stores a pointer that reactivates the cortex rather than the content itself (Teyler & DiScenna, 1986).

The models are small and open: Qwen2.5-1.5B-Instruct, Qwen3.5-2B and Qwen3.5-9B, all frozen. The test is always the same. In session 1 the user says something (“My dog’s name is Pepper.”, “I can’t stand jazz music.”). In session 2, a fresh chat with none of that text, the user asks something where it matters. Each result is reported next to no memory (the floor) and in context, where the original sentence is written into the session-2 prompt (what perfect remembering would look like).

2Two ways to put a memory back

Some background first. A transformer reads text as a row of positions, roughly one per word piece. Each position carries a vector, the residual stream, that every layer reads and adds to. At each attention layer, each position also leaves behind a key and a value. A later position finds information by attention: it compares its query with all the keys and reads a weighted mix of the values. The keys and values of everything read so far are the KV cache. The point that matters here: information that sits at a position can be looked up by attention. A vector that is added everywhere has no position of its own.

Seahorse has tried two ways of putting a memory back into a new conversation.

  • The push (paper 1). The model reads the user’s message twice: once with the experience and once with a reference in its place, for example the opposite statement. The difference in the residual stream, averaged over the words that follow, is stored as one vector, filed under a gist key of the conversation. In a later chat, when the current gist clearly matches a stored key, the vector is added, times a strength α, at every position in three late layers. This is activation steering used as a memory.
  • The slice (since then). The model reads the experience once. Seahorse keeps the keys and values of two positions, the name and the full stop after it, at every attention layer: a slice of the KV cache. In a later chat, if the question mentions the stored subject (“my dog”), the slice is put into the user’s turn, just before the question, as if the user had said it again. Nothing is added anywhere else. On the hybrid Qwen3.5-2B, only 6 of 24 blocks use attention; the other 18 are recurrent (Gated DeltaNet) blocks that summarise everything read so far in a fixed-size matrix, the recurrent state. There, the slice also keeps that state.

3What a pushed vector can carry

Paper 1 (arXiv:2610.14958) tests the push in one consolidated run, core_v1, on Qwen3.5-2B and Qwen3.5-9B (the 9B at the same relative depth). The claims and their pass/fail rules were written down before the run. It uses {{N_LEAN}} leanings (vegetarian, early riser, prefers quiet, …), {{N_DIS}} dislikes (“I can’t stand jazz music.”), {{N_FACTS}} facts and 50 unrelated prompts, at doses α = 0.5 to 3 per layer. The controls are a random vector, another memory’s vector, a placebo experience (“I had a coffee this morning”) and the gate removed. A judge model (Qwen3.5-9B) labels every answer for direction and coherence; an incoherent answer counts as zero, however many target words it contains.

3.1 It stays out of unrelated answers

On unrelated prompts, {{C1_SAME_2B}} (2B) and {{C1_SAME_9B}} (9B) of answers are token-for-token identical to the no-memory answers. The gate does this: with it removed, only {{C1_OFF_2B}} and {{C1_OFF_9B}} stay identical.

3.2 Leanings: real, modest, and only near α ≈ 1

At α = 1 per layer, answers lean toward the stored preference by {{LEAN1_2B}} on the 2B and {{LEAN1_9B}} on the 9B. That is significant, but small next to the in-context gain, and uneven across items: strong for early riser, prefers quiet, vegan and vegetarian; nothing for celiac, lactose intolerant or has young kids. At α = 2, incoherent answers jump from {{INC1_2B}} to {{INC2_2B}} (2B) and from {{INC1_9B}} to {{INC2_9B}} (9B), and the coherent lean no longer clears zero ({{LEAN2_2B}}; {{LEAN2_9B}}). The pre-registered claim required a gain at both doses, so it failed.

A correction to earlier versions of this page. They reported a large vegetarian effect from counting preference words. Word counts rise with the dose even when the text breaks down: here, the word-list lean gain on the 2B goes from {{LEX1_2B}} at α = 1 to {{LEX2_2B}} at α = 2, while the judged lean does not rise. The earlier count was inflated by incoherent text. The judged, pre-registered result above replaces it.

3.3 Facts come out as a word, not a statement

Asked to use a stored fact (“Write a short birthday message to my sister.”), the judged clean use, meaning the right fact used correctly in a coherent answer, is at most {{PUSH_MAX_2B}} (2B) and {{PUSH_MAX_9B}} (9B) at any dose, against {{FACT_CTX}} in context. At α ≥ 2, {{MENTION2}} of answers mention the fact without using it cleanly: “Petra Petra Petra …”. Injecting the same vector at earlier layers does not turn it into knowledge either; it fades, or garbles the answer (“My name is Omar.”).

The reason shows in the vector itself. Read through the model’s output vocabulary (the logit lens), a fact shift ranks the right name in the top 10 only from relative depth {{C6_DEPTH_2B}} (2B) and {{C6_DEPTH_9B}} (9B) onward; at half depth its median rank is about {{C6_RANK_HALF}}. A stored fact shift is an intention to say a word, present only near the output.

3.4 No premises

A premise is a fact the model can reason with. The test is a balanced pair of yes/no questions, one where Yes is right (“Is my dog called Pepper?”) and one where No is right (“Is my dog called Max?”); averaging the two accuracies means a model that drifts toward “No” scores 0.5, not more. No dose raises it. With a fact memory at α = 1, balanced accuracy stays at {{BAL1}} on both models, the same as with no memory ({{BAL0}}), against {{BALCTX}} with the fact in context; at α = 2 the 2B even loses ({{DBAL2_2B}}). The shifts in the Yes/No margins are a general tilt, not knowledge. The push also gets the owner wrong: pushed toward teal, the model said “Teal is my favourite colour!”. Section 5 shows that this, too, is a failure of the push, not of memory in general.

3.5 What you subtract decides the direction

A pushed vector is always “the state with the experience, minus a reference”. Three references matter: the opposite statement (“I love jazz”), the same message without the experience, and the mean over eight alternatives of the same kind (“I can’t stand rock / classical / … music”).

Only the opposite keeps a dislike a dislike: {{OPP_2B}} (2B) and {{OPP_9B}} (9B). Subtracting the alternatives turns every dislike into a like ({{CEN_2B}}, {{CEN_9B}}), and subtracting “without” does the same on most items ({{WO_2B}}, {{WO_9B}}). Inside the model, “I can’t stand jazz” is mostly jazz with a faint negation, so any reference without jazz in it leaves jazz behind. A preference has a what (the concept) and a which way (the sign), and no single subtraction keeps both.

3.6 How far to trust the judge

No human labels were collected. Instead, every core_v1 answer was re-judged by models from other families: gpt-oss-20B, Gemma-4-12B and Llama-3.1-8B, plus Qwen3.6 as a same-family reference that never votes.

{{TBL_PANEL}}

The majority votes are over the original judge plus the three cross-family judges, or over the three cross-family judges alone. The fact result (C3) and the direction result (C5) hold under the original judge, under gpt-oss and Gemma-4, and under both majority votes; under gpt-oss and Gemma-4 the alternatives push dislikes the wrong way even harder ({{CEN_PANEL}}). The leaning result (C2) is judge-sensitive: it fails under every single judge but holds under both majority votes, because the original judge is the strictest about coherence. Llama-3.1-8B is not trusted on its own: it labelled most fact answers as using the fact, including many where the name never appears. The same-family Qwen3.6 agrees on C3, and on C5 for the opposite and the alternatives, but not for “without”.

4Why: facts are bound by position

Work on how models track entities says a fact in context is bound through positions. The entity and its attribute carry a shared binding tag, an internal marker of which entity goes with which attribute (“the first pair”, “the second pair”), and attention heads find the attribute’s position and copy from it (Feng & Steinhardt, 2024; Prakash et al., 2024). Facts stored in the weights work differently: they are loaded onto the subject’s own position (Geva et al., 2023). Either way, a position does the work, and a push supplies none.

To see where our models read a fact from, the run takes “My dog’s name is Pepper. What’s my dog’s name?” and the same prompt with Rocky. It copies the internal state at one position and one layer from the Pepper run into the Rocky run, and measures how much of the model’s Pepper-versus-Rocky preference moves.

Patching the question’s subject moves {{S0_SUBJ_MAX}} of the preference at every layer. Patching the name moves everything up to layer {{S0_25_FULL_TO}} (Qwen2.5) or {{S0_2B_FULL_TO}} (Qwen3.5-2B), then falls: on the 2B to {{S0_2B_DROP_V}} by layer {{S0_2B_DROP_L}}, because by then the answer position has already read the name. On Qwen2.5, blocking the answer’s view of the name costs {{S0_KO_ATTR}} of the in-context gain, and only in the last layers. So the answer pulls “Pepper” from Pepper’s position, late; “my dog” is a label. It may still carry a pointer (a binding tag), which this patch cannot see, but it holds no copy of the value. Writing a stored state at the subject, the plan before this test, gave clean use {{SUBJ_CLEAN}}.

5What a stored slice carries

If the value is read from its own position, the memory should give the model that position back. The slice does: the keys and values of the name and the full stop after it, stored in session 1 and put into the user’s turn in session 2 when the question mentions the subject. The tests use {{N_PRIMARY}} fact items (a dog’s, cat’s, sister’s, brother’s, grandmother’s, best friend’s and boss’s name), with prompts that need the fact without asking for it, judged by the majority of three judges from three families.

On Qwen2.5-1.5B, two stored positions give clean use {{R25_MIN_CI}}, the whole turn {{R25_FULL}}, and the sentence in context {{CTX25}}. The same two tokens given as plain text in an earlier turn give {{TMIN25}} (difference {{TMIN_DIFF_25}}), and {{TMIN25_DIRECT}} on the direct question. The slice carries more than its tokens because its keys and values were computed with the whole sentence in view. A slice stored after an unrelated exchange, and used without it, still gives {{R25_ORPHAN}}.

  • The gate keeps it selective. With the subject gate, unrelated answers are unchanged {{UNREL_GATED}} of the time; with the same slice always on, {{UNREL_UNGATED}}.
  • Ownership is fixed. The assistant claims the fact as its own in {{SELF_RFULL}} of answers, the same as with the sentence in context ({{SELF_CTX}}). The slice sits in the user’s turn, so it reads as the user’s.
  • Two positions are weaker on the direct question. “What’s my dog’s name?” gets {{R25_MIN_DIRECT}} with two positions, against {{R25_FULL_DIRECT}} for the whole turn.
  • A wrong slice is used as confidently as a right one. Another fact’s slice, under this fact’s gate, puts the other value into {{SWAP_CONFAB}} of answers.

What is and isn’t new. Putting back the whole turn is exactly prompt caching: the whole sentence as text in an earlier turn gives the same result (difference {{TFULL_RFULL}}). Reusing cached keys and values across requests, and fusing separately cached pieces, are known systems techniques (Prompt Cache, Gim et al., 2024; CacheBlend, Yao et al., 2025). What this work adds is that two positions are enough, that the cache can be gated and moved into a new conversation, that it beats the same tokens as text, and the explanation of why: the value lives at the attribute’s own position.

5.1 On a hybrid model: the value and the verification come apart

Qwen3.5-2B attends at only 6 of its 24 blocks. There, the two-position slice alone gives clean use {{R2B_KV6}}, and it refuses direct questions (“I don’t know your dog’s name!”; {{R2B_KV6_DIRECT}} on the direct question). Adding the recurrent state from the same stored turn gives {{R2B_MINSTATE_CI}} (direct question {{R2B_MINSTATE_DIRECT}}; change {{ST_MINUS_KV}}), stored after an unrelated chat {{R2B_ORPHAN}}, in context {{CTX2B}}. The state alone gives {{R2B_STATEONLY}} clean use.

Teacher-forced, the split is clean. The two attention positions carry the value (+{{TF_KV6_NATS}} nats, against +{{TF_CTX_NATS}} in context), but yes/no stays at {{TF_KV6_YN}}. The recurrent state alone verifies (yes/no {{TF_STATE_YN}}) but carries only part of the value (+{{TF_STATE_NATS}} nats) and never recalls it in generation. The recognition is in the recurrent state, not the convolution buffer ({{TF_CONV_YN}}). Together, yes/no is {{TF_MINREC_YN}}. This matches Afendulev et al. (2026), who find within one session on Qwen3.5 that attention carries exact retrieval and the recurrent state carries familiarity and response mode. Two caveats. Their state also says yes to associated but wrong items; our wrong answers are unrelated names, so a control with associated names is still owed before calling this recognition of the specific fact. And the state is not small: about {{STATE_NUMBERS}} numbers ({{STATE_MB}} in fp32) whatever the length of the text. Why the attention-only slice refuses is open: a missing response mode, or a missing “I know this entity” signal.

6Where it breaks

6.1 Separately stored facts swap partners

Two facts, each stored in its own session, are put back together for one question: an older sister Petra and a younger sister Maria, or a dog and a cat.

Stored separately, the model gives the partner’s name in {{COLL_RANGE}} of answers, even for a dog and a cat, and whether or not the positions overlap. Encoded together, both models answer correctly about as often as with both sentences in context ({{JOINT_CORR}} against {{CTX2_CORR}}). The likely reason is the binding tag. Each slice was stored as the only pair in its conversation, so both carry the “first pair” tag, and the question cannot tell them apart. That reading is inferred. The tag direction is real: measured as Feng & Steinhardt do, it flips which partner the model prefers in {{ID_VALID}} of held-out contexts in the late layers, against none for a random direction. But adding it to a stored slice does not reduce the swaps (change in confusion {{ID_REPAIR}}). For now, the working fix is to re-read memories that belong together in one pass.

6.2 Retrieval works, and its errors are confident

With {{GK_N}} stored facts on Qwen2.5-1.5B, a key built from the subject’s words picks the right slice for {{GK_K1}} of direct questions, depending on the layer, with no collapse as the store grows (a key from the whole text: {{GK_K2}}; unrelated prompts open a gate {{GK_FF}} of the time). The right slice makes the right name as likely as the sentence in context does (+{{GK_ORACLE_NATS}} vs +{{GK_CTX_NATS}} nats). A wrong slice is worse than none: it pushes the right name down ({{GK_SWAP_NATS}} nats) and the model states the wrong value {{GK_WRONG}} of the time. In generation, on prompts that need the fact, the right slice gives {{GK_USE_ORACLE}} and the key’s own pick {{GK_USE_KEY}}, with {{GK_USE_CONFAB}} confident wrong values. The right slice is in the top two {{GK_TOP2}} of the time, so checking the pick before using it is the obvious next piece.

One open check: on a pool of extra facts, asked only the direct question, the right slice did worse than in context. The direct question is also where two positions are weakest on the hand-picked facts, and teacher-forced the right slice matches the sentence in context on every one of the {{GK_N}} facts, so this is most likely a prompt-type effect. It is being checked.

7The model can write its own references

Every pushed preference in paper 1 was written from hand-made comparison sentences: an opposite and eight alternatives. A real conversation has only the experience. So a model (Qwen3.5-9B) was given the experience sentence alone and asked to write the opposite and the alternatives; the memory then ran on Qwen3.5-2B as before.

On dislikes, the generated opposite moves answers the right way ({{GEN_OPP_DIS}}, hand-written {{HAND_OPP_DIS}}), and the generated alternatives move them the wrong way ({{GEN_CEN_DIS_CI}}, {{GEN_CEN_WRONG}} of items wrong). That is paper 1’s direction result again, with no human-written reference, and it holds under every judge. The generated sentences are not copies of the hand-written ones, and the model kept some odd clauses (“I have celiac disease, so I can eat gluten.”), but the effect survives.

The open piece is the sign. A general like/dislike direction reads the sign of the 23 signed items with accuracy {{S3_ACC}}, about chance. It reads every dislike right but calls restrictions negative: vegan, lactose intolerant, a tight budget. “Avoid” is not “dislike”; the sign has to be read relative to the stored concept. With the true sign, concept × sign is the best leaning memory so far ({{CS_ORACLE_LEAN}} on leanings, {{CS_ORACLE_DIS}} on dislikes); with the automatic sign, leanings do not improve ({{CS_AUTO_LEAN}}), because restrictions get the wrong sign.

On PrefEval (Zhao et al., 2025), 200 preferences that no one wrote references for, the generated opposite improves preference-following under every judge, modestly: {{PE1}} at α = 1, against {{PECTX}} with the preference in context.

8Where this is going

The design that follows from these results has two channels and an offline phase.

  • Slices for content. Facts, and anything else a later question has to look up, are stored as the model’s own keys and values at a few positions (plus the recurrent state on hybrid models), filed under their subject, and put back in the user’s turn.
  • The push for abstracted leanings. The one job the push does well is a whole-answer leaning, at a low dose, stored with its sign.
  • An offline “dreaming” phase for what one forward pass at write time can’t do: re-encoding memories that are used together so they get distinct binding tags, abstracting a leaning from many episodes, and choosing what is worth keeping.

Open problems, roughly in order:

  • Verify a retrieved slice before using it, and abstain when two candidates are close: a wrong slice is worse than none.
  • Read the sign relative to the concept, so “I’m vegan” is stored as a leaning toward a diet and away from a food.
  • Explain why an attention-only slice refuses although the value is there.
  • Train a small read adapter on the frozen model. The training-free reads now have clear limits (retrieval, the sign, the refusals), and trained fast-weight memories such as FwPKM (Zhao & Jones, 2026) show that learning when to read a memory helps. This is the likely next step.

A second write-up, on what binds a memory (the push, the slice, and the hybrid’s split), is in progress, with more controls and a second model family running now.

9Limits

  • Small models, mostly one family. Qwen2.5-1.5B, Qwen3.5-2B and Qwen3.5-9B. The slice results have no finished runs on the 9B or outside the Qwen family yet.
  • Few items for the slice results. {{N_PRIMARY}} hand-picked facts carry most of Sections 5 and 6, so the intervals are wide; retrieval used {{GK_N}} facts.
  • The judges are models. No human labels were collected. The cross-family panel agrees on the fact and direction results; the leaning result depends on the judge.
  • The recurrent state is large ({{STATE_MB}} per memory on the 2B), so on hybrid models the slice is compact only for long episodes.
  • The mechanism is cache reuse. The contribution is which part of the cache carries a fact, how little is needed, and why combining separately stored pieces fails, not the act of reusing a cache.
  • Some readings are inferred. The binding-tag explanation of the swaps, and the reading of the state’s yes/no as recognition, still lack their decisive controls.

Definitions

  • Clean use: on a prompt that needs the fact without asking for it, the answer uses the right fact, correctly, in a coherent answer.
  • Judged lean: +1 if the answer coherently recommends toward the user’s trait, −1 if away, 0 if neutral or incoherent. Gains are paired against no memory on the same prompt with the same random numbers.
  • Balanced yes/no: the mean of the accuracies on Yes-correct and No-correct questions about the fact; 0.5 is chance.
  • Loop: an answer whose repeated-4-gram rate is at least 0.3.
  • Incoherent: loops, fragments, word salad or off-task text, as labelled by the judge.
  • Loop-matched dose: the highest α at which at most 10% of answers loop, so references are compared at a fair strength.
  • Intervals: 95%, from a bootstrap that resamples items, then prompts within items (2,000 draws).

Judges

The original judge is Qwen3.5-9B with a fixed rubric for direction and coherence. The panel re-judged paper 1’s answers with gpt-oss-20B, Gemma-4-12B and Llama-3.1-8B (not trusted as a single judge after it failed a sanity check; it counts as one voter in the majority votes), plus Qwen3.6-35B-A3B as a same-family reference.
