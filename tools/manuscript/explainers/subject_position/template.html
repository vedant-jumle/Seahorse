Does a stored memory need the subject’s position?

A memory of “My dog’s name is Pepper.” can be stored as the model’s own cached state for just two tokens, Pepper and .. That memory knows the name but often refuses when asked “What’s my dog’s name?”. This test asked which extra stored position fixes that.

Answer: the subject’s position (dog), and only that one. Adding it makes the model answer instead of refuse, almost as well as storing the whole sentence. Adding is or name does nothing. The name itself is equally available in every version. What the subject changes is whether the model is willing to say it.
Background

The problem this test was built for

Seahorse’s working fact memory is a slice: in session 1 the model reads the sentence once, and we keep its attention memory (the keys and values, K,V) for a few token positions. In session 2, a fresh chat, we put those entries back in front of the user’s question. The model then behaves as if it had read the sentence, without the text being there.

The smallest slice that worked kept two positions: the name and the full stop after it (Pepper ., called R-min). On prompts that use the fact (“Write a note to the vet about my dog”), it was as good as having the sentence in the prompt. On the direct question it was weaker: 0.66 clean answers, against 0.91 for the whole sentence. The rest were refusals like “As an AI, I don’t have access to your personal information.”

So the model had the name and still refused. Two explanations fit:

  • Two-step lookup. To answer “What’s my dog’s name?”, the model first finds the entity (dog) in its context, then fetches the attribute tied to it (Pepper). That is how interpretability work describes in-context recall. R-min threw away the dog’s position, so step 1 had nothing to find.
  • More evidence. The model answers when it has enough evidence that it was told something. Two positions are just less evidence than the whole sentence. Any extra stored position should help.

The test separates them by adding one position at a time, keeping the size equal, and seeing whether it matters which one.

Technical

Earlier results this builds on (all in docs/dreaming/01-binding.md): R-min clean use 0.86 on use prompts and 0.66 [0.40, 0.89] on direct questions (Qwen2.5, addendum 2); R-full 0.91. Teacher-forced, the right slice equals ctx on the target (about +9.5 nats). Stage 0 showed the answer reads the value from the attribute’s own position late in the network, and the question’s subject holds no copy of the value.

The two-step reading follows Prakash et al. (entity tracking: position detectors, then value fetchers) and the Lookbacks paper (the attribute token carries the value plus an order-ID address). The “more evidence” reading predicts any added position helps roughly in proportion to how much context it carries.

Setup

What was stored, and how it was put back

Facts. 45 facts about people and pets: the 7 hand-written ones from experiment 1 (dog, cat, sister, brother, grandmother, best friend, boss) and 38 from the fact pool (hairdresser, ferret, mother-in-law…), all in the form “My X’s name is V.”.

What was measured. Nothing was generated and judged. Instead, for each question the model’s probabilities were read directly (“teacher-forced”):

  • Answer score: how likely the model is to begin “Your dog’s name is”, rather than a refusal. This is the main measure.
  • Name gain: once forced to begin “Your dog’s name is”, how much more likely the right name is than with no memory.
  • Yes/no: “Is my dog called Pepper?” and “Is my dog called Max?”, scored so that always saying yes gets 0.5.
  • Attention: where the model looks when it reads the question.

Scores are in nats, the natural log of a probability. A difference of +1 nat means about 2.7 times more likely, +2 nats about 7 times.

Technical
  • Model: Qwen2.5-1.5B-Instruct, fp32, every layer full attention (28 blocks). Run locally on an RTX 4060 (3.7 min, peak 6.3 GB).
  • Harvest: one pass over [chat head][experience user turn]. K,V kept at every layer for the chosen positions, at their stored RoPE positions; the question turn starts where R-full’s would (n_head + n_seg). R-min’s kept indices are asserted equal to bind.splice_keep("R-min").
  • Subject token: the last token of the subject span inside the experience sentence (e.g. dog, friend). 12 pool subjects end in a word piece (er for hairdresser, -law). Multi-token values keep their first sub-token plus the next token.
  • Pool facts: sample_pool seed 0, hand-written slots excluded, as in addendum 7 C. 10 attribute facts (job, instrument…) were run but are reported separately.
  • Checks that fail the run: R-full teacher-forced = the sentence as a prior user turn (max |Δlogit| 2.5e-5); kept-entry counts; subject index before value index.
answer score = Σ_t log P(prefix_t | question, prefix_<t) with prefix = “Your dog’s name is”
name gain = log P(target | question + prefix) − same under no memory
yes/no = ½ [acc(Yes probes) + acc(No probes)], “yes” if log P(Yes) > log P(No) at the first token

Statistics: 95% percentile bootstrap over facts, 2000 replicates, seed 7; contrasts paired on the same fact. Pre-registered in experiments/dream_subj/PREREG.md (commit 1cec0e8) before the full run.

Result 1

Only the subject makes the model answer

With no memory the model almost never starts with “Your dog’s name is” (−9 nats). The 2-position slice moves it most of the way (−2.3). Adding the subject takes it to −1.0, close to the whole sentence (−0.7). Adding is or name leaves it where R-min was.

Technical: the pre-registered rule

Rule (direct question, answer score, all 45 person/pet facts): “subject position matters (two-step lookup)” if the paired CIs of R+subj − R-min, R+subj − R+fill and R+subj − R+rel all have lower bound > 0. All three do.

Result 2

It holds fact by fact, not just on average

Each line is one fact, from its R-min score (left) to its score with the extra position (right). Adding the subject raises the score for 42 of 45 facts. Adding “is” raises it for 26, about a coin flip, and “name” more often lowers it.

Where it doesn’t hold as well. On the 7 hand-written facts alone the gain is smaller and not significant (+0.46 [−0.20, 1.13]). Three of their questions don’t fit the forced opening: “Do you remember my sister’s name?” is naturally answered “Yes, …”, and two ask what the pet is “called”. Their yes/no gain is significant (+0.14). The 38 pool facts carry the result (+1.47 [1.16, 1.81]).

Result 3

The subject changes the decision, not the content

This is the most informative part. Look at the model’s very first word. With R-min, a refusal opening (“I…”, “Sorry”, “As an AI…”) still takes a quarter of the probability. With the subject added it nearly vanishes. Yet once the model is made to start “Your dog’s name is”, the right name is equally likely under every slice. The name was there all along. The subject decides whether the model commits to saying it.

Left: the decision moves a lot. Right: the content barely moves. Every slice gives about +9.9 nats on the name (contrasts ≤ 0.1 nat), the same as the sentence in the prompt. So “more evidence” as a single quantity doesn’t describe this. Content and the willingness to answer come apart, and the subject entry controls the second.

Technical

Refusal start here = P(“I”) + P(“Sorry”) + P(“As”) at the first assistant token; the report’s refusal mass counts only “I” + “Sorry” (0.15 → 0.02). “I” can start a non-refusal (“I remember…”), so this is a proxy. “The name first” is the first sub-token of the value. The answer score misses answers that start with the name, which is why R+subj’s score (−0.96) is slightly below R-full’s (−0.66) while its refusal mass is the same.

Name gain contrasts (all 45): R+subj − R-min +0.02 [0.01, 0.04]; R+subj − R+fill +0.07; R+subj − R+rel +0.09. Significant but tiny next to the answer-score contrasts (1.2 to 1.5 nats).

Result 4

Yes/no confirmation follows the same pattern

“Is my dog called Pepper?” / “Is my dog called Max?”: R-min gets 0.82. With the subject, 1.00, as with the whole sentence. The two same-size controls are slightly worse than R-min. Swapping the full stop for the subject (R-subj2, still 2 positions) gives 0.97.

Result 5 · descriptive

Where the model looks: two steps, at two depths

With the 3-position slice in place, we read where attention goes when the model processes the question. Two things stand out. In the early and middle layers, the question’s own word “dog” looks at the stored “dog” entry far more than at the stored name. In the last layers, the position that will produce the answer looks at the stored name. That is the shape the two-step reading predicts: first find the entity, then fetch its value.

Technical

Eager attention with the injected cache; weights averaged over heads, then over facts. From the question’s subject token, attention to the stored subject exceeds attention to the stored name in layers 0–13 (largest 0.13 at layers 5 and 8), then the name dominates. From the last prompt token, attention to the stored name rises in layers 23–27 (0.12 at layer 27); layers 20–21 show a small subject peak. R-subj2 has the same profile. Most attention in every layer goes to the chat head and the question’s own tokens, which are not plotted.

Interpretation

What it means, and how it fits what came after

In plain terms. To answer a direct question about something the user said, the model needs two things: the content (the name), and something that lets it commit to an answer. A stored slice can carry the first without the second. The subject’s own stored position supplies the second. For a memory, the practical rule is: keep subject + value + full stop. Three positions do almost everything the whole sentence does.

Established here

The subject position specifically, not any third position, restores answering and yes/no. Content is unchanged across slices.

Addendum 7 (same day)

A “told” direction (ctx − no memory, from other facts) also restores direct answering from the 2-position slice (Qwen2.5 0.66 → 0.94). So the refusal is a response gate, separate from content.

Addendum 8 (29 Oct)

That “told” direction is mostly a generic “answer personal questions” direction. And for two stored facts, the binding that keeps them apart sits at the subject’s positions, but only when the facts were encoded together.

Reading (inferred)

The subject entry may do two jobs. Alone, from any harvest, it opens the response gate for its fact. Encoded jointly with other facts, it also carries the tag that says which value belongs to which subject.

What it can’t tell us yet.

  • Lookup or mention? The result fits a real binding lookup (find “dog”, follow its tag to “Pepper”), and also a simpler rule (“this subject came up before, so answering is allowed”). The cheap test that would separate them: restore a “dog” entry from an unrelated sentence (“My dog loves long walks.”) alongside the Pepper slice. If mention is enough, it helps as much as the real one. If it is a lookup, it doesn’t.
  • No generation. Everything is teacher-forced. The judged clean-use rate on direct questions with the 3-position slice hasn’t been measured.
  • One model, one template. Qwen2.5-1.5B and “My X’s name is V.” only. The hybrid 2B (where the recurrent state seemed to supply this signal) and Llama weren’t run.
  • Use prompts untested. The prediction that the subject matters more for direct questions than for use prompts couldn’t be checked: the only use-prompt measure was saturated.
  • Attribute facts (job, instrument; 10 facts) show a different, noisy pattern: there “is” helps and the subject alone hurts. Their “subject” is often a weak match.
