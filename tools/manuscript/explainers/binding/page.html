Seahorse · explainer

What “across positions” means

A transformer doesn’t hold a conversation as one vector. It holds a table: one residual vector per token position. Concepts inside one vector are (roughly) added together. Which concept belongs to which is recorded by where things sit in that table, and attention reads it back by picking a position.

“Binding is across positions” = the link between dog and Pepper is not stored inside any single vector. It is stored by Pepper sitting in its own slot, tagged as part of the dog pair, where a question can find it.
The problem with one vector

This is the classic binding problem: red·square + blue·circle and blue·square + red·circle add up to the same bag of features. Once you sum over positions, the information about which name belongs to which pet is gone. Nothing you do to that one vector afterwards can recover it.

How the model reads it back

Attention fetches by slot, not by content

Now ask “What’s my cat’s name?” The model doesn’t search for a vector that says “cat’s name”. Interpretability work on entity tracking (Prakash et al.; the Lookbacks paper) finds a chain: work out which pair the question is about, carry that address to the answer position, then let value-fetching heads attend to the slot with that address and copy what’s there. The key move is step 2: attention’s score is a dot product between a query and each position’s key, so it can single out one column. A table gives it columns to choose between. A pooled vector gives it one, already mixed.

One subtlety. “Position” here means a separate slot attention can pick, carrying its tag. It does not mean the absolute index. In Seahorse’s collision test, shifting a stored slice to a later index changed nothing (confusion 0.35 vs 0.37). The tag, set when the slice was stored, does the work, not the index.

What this explains in Seahorse

Four ways to store a fact, one rule

Every Seahorse result on facts follows from whether the stored thing keeps its own slot and a tag the question can match. Numbers are clean use of the fact in a coherent answer, from the project’s runs.

One way to write it down · an interpretation

Sums inside a slot, a tensor product across slots

Status: a lens, not a measured finding. Tensor-product structure has been confirmed in small RNNs on synthetic tasks (McCoy et al. 2019; ROLE). Encoders trained on natural text looked more like a bag of words, and the TP-Transformer had to build binding into attention explicitly. No paper has tested whether an LLM’s sequence actually has this structure. The maths below is a tidy way to describe the Seahorse results, not evidence for them.

Call the content at position i its filler fᵢ, and what identifies the slot (its place and tag) its role rᵢ. The whole sequence then behaves like a tensor product representation (Smolensky):

sequence ≈ Σᵢ fᵢ ⊗ rᵢ

Attention undoes the binding. The query names a role; the dot product with each key picks the matching slot; the value comes out:

answer ≈ Σᵢ softmax(⟨q, kᵢ⟩) · vᵢ → f_j where r_j matches q

Pooling a shift averages over the role index. In tensor language that contracts the role away, and only the bag of fillers is left:

pooled = (1/n) Σᵢ fᵢ ← no rᵢ, no binding

Where the picture is simplified

Caveats

  • Each column is already contextual. By the late layers, Pepper’s slot carries “dog’s name” as well as “Pepper”, because attention has mixed earlier tokens into it. That is why a stored 2-position slice beats the same two tokens given as text (0.86 vs 0.27): the slice was computed with the whole sentence in view.
  • The tag is a direction, not a label. Binding IDs are vectors added at the entity and attribute slots. Seahorse found the direction is real in late layers (it flips partners in 75% of contexts) but adding it to a separately stored slice did not stop the swaps. Storing the slice in order did (next points).
  • One slot can hold a lot, and “roughly added” is a hypothesis. MLPs build new features inside a slot. For a multi-token word like “peanut butter”, the MLP writes a whole-word vector at the last token, and information about the separate parts fades in early layers (Kaplan et al. 2025; Feucht et al. 2024). So a compound is not simply its parts plus an extra feature. Hierarchies do look additive and orthogonal (Park et al. 2025), but some features are irreducibly multi-dimensional (Engels et al.), and no one has rigorously tested additivity for compound concepts in a modern LLM. The claim here is only that relations between things in different slots are read by attention picking slots.
  • What is measured and what is inferred. Measured: the answer reads the value from the attribute’s own slot, late (Seahorse stage 0; Prakash et al.; Lookbacks). Pooling loses the binding (it has to, mathematically). Separately stored slices swap partners because of storage order: a slice stored on its own is always “the first pair”. Storing the new fact after a dummy fact, so it is written as the second pair, cuts partner confusion from 0.33–0.41 to 0.09–0.15 on three models. The binding sits at the subject’s positions, and only joint encoding writes it there. Storing in order removes most swaps up to 3 facts and about halves them at 5; for five same-kind facts, joint encoding is still needed. Inferred: that a shared tag is exactly what collides (storing both facts as the second pair brought the swaps back only on Qwen2.5), and the tensor-product reading above.
  • Hybrids differ. In Qwen3.5-2B most layers are recurrent (Gated DeltaNet) and fold all positions into one state. That state gives recognition (yes/no 0.93) but not recall (0.00). Recall still came from the attention slots.
